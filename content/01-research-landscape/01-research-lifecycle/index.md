# AI 연구의 생애주기

논문을 읽으면 연구가 모델에서 시작하는 것처럼 보인다. 방법 절이 가장 길고, 그림의 대부분이 아키텍처와 학습 곡선이다. 그러나 실제 연구의 시간과 결정은 대부분 모델 바깥에서 쓰인다. 무엇을 예측할지 정하고, 어떤 데이터를 어떻게 나눌지 정하고, 무엇과 비교해 얼마나 좋아야 성공인지 정하는 일이다. 이런 결정이 잘못되면 모델이 아무리 좋아도 결과는 쓸모가 없다.

이 장은 AI 연구를 하나의 **생애주기**(lifecycle)로 본다. 현실의 문제에서 출발해 후속 연구로 이어지기까지 어떤 단계를 거치는지, 각 단계가 무엇을 산출하고 어떤 가정을 깔고 있는지, 어디서 앞 단계로 되돌아가는지를 정리한다. 이 지도는 이 책의 나머지 부가 각각 어느 단계를 깊게 다루는지 보여 주는 색인이기도 하다.

## 학습 목표

- 연구의 전체 단계를 설명한다
- 각 단계에서 내려지는 결정과 가정을 식별한다

## 문제에서 후속 연구까지

**왜 단계로 나누는가.** 연구가 실패했을 때 "모델이 나빴다"는 진단은 거의 항상 너무 이르다. 데이터 분할이 문제를 바꿔 놓았을 수도, 평가 지표가 연구 질문과 어긋났을 수도, 정답 label 자체가 잡음투성이였을 수도 있다. 단계를 나누면 결과가 이상할 때 **어느 결정을 다시 볼지** 물을 수 있다.

**아홉 단계.** 이 책은 AI 연구를 다음 아홉 단계로 나눈다. 각 단계는 다음 단계가 쓸 **산출물**을 남기고, 그 산출물에는 그 단계에서 내린 **가정**이 들어 있다. 예시는 "리튬이온 배터리 셀의 남은 수명을 초기 사이클 데이터로 예측한다"는 가상의 연구다.

| 단계 | 산출물 | 이 단계의 대표 가정 | 배터리 예시 | 주로 다루는 곳 |
|---|---|---|---|---|
| 1. 현실의 문제 | 문제 진술 | 이 문제를 풀면 누군가의 결정이 나아진다 | 셀 수명 시험은 수개월 걸려 신소재 평가가 느리다 | 23.4장, 23.13장 |
| 2. 연구 질문 | 검증 가능한 질문 | 질문의 답이 현실 문제에 기여한다 | 처음 100 사이클로 수명을 예측할 수 있는가? | 23.4장 |
| 3. 수학적 정의 | 입력·출력·평가 단위·성공 기준 | 예측 시점에 이 입력이 존재한다, 이 지표가 성공을 대변한다 | 입력: 초기 사이클의 전압·용량 곡선, 출력: 용량이 80%가 되는 사이클 수 | 1.3장, 12.3장 |
| 4. 데이터 | 수집·정제된 데이터셋과 분할 | 데이터가 일반화 대상을 대표한다, label이 정확하다 | 셀 단위로 학습·검증·테스트 분할 | 15부 |
| 5. 모델 | 모델 구조와 baseline | 모델의 귀납적 편향이 문제에 맞다 | 선형 baseline, 트리 앙상블, 작은 신경망 | 16–18부, 24부 |
| 6. 학습 | 학습된 파라미터, 학습 기록 | 최적화가 충분히 수렴했다, 하이퍼파라미터 탐색이 공정했다 | 검증 데이터로 하이퍼파라미터 선택 | 10부, 17부, 22부 |
| 7. 평가 | 지표, 오차 분석, 불확실성 | 테스트 데이터가 운영 환경을 대표한다, 차이가 잡음보다 크다 | 처음 보는 셀에서의 오차와 구간 | 12.5장, 16.6장, 21부 |
| 8. 해석 | 주장과 그 범위 | 관찰된 차이의 원인이 제안한 요인이다 | 어떤 초기 특징이 수명과 관련되는가 | 21.5장, 23.6장 |
| 9. 후속 연구 | 다음 질문, 공개된 코드·데이터 | 남이 결과를 재현할 수 있다 | 다른 화학 조성의 셀에서도 되는가? | 22.2장, 23.8장, 31.2장 |

표의 가정 열은 대개 논문에 적히지 않는다. 그러나 결론이 어디까지 유효한지는 이 열이 정한다. 예를 들어 4단계의 "데이터가 일반화 대상을 대표한다"는 가정이 틀리면, 7단계의 테스트 점수는 높아도 실제로 쓸 수 있는 범위는 좁다.

::quiz{id="lifecycle-return-point"}

**되돌아가는 지점.** 아홉 단계는 한 방향으로만 흐르지 않는다. 실제 연구는 뒤 단계에서 발견한 문제 때문에 앞 단계로 자주 돌아간다. 이를 **되먹임 고리**(feedback loop)라 한다. 대표적인 고리는 다음과 같다.

- **평가 → 수학적 정의.** 테스트 점수는 좋은데 새 장비의 데이터에서 무너진다. 일반화 대상을 정하지 않았던 것이다. 분할을 다시 설계해야 하고, 때로는 질문 자체를 좁혀야 한다.
- **학습 → 데이터.** 손실이 이상하게 빨리 0에 가깝다. label이 입력에 섞여 들어간 누수(leakage)를 의심하고 데이터 단계로 돌아간다(15.4장).
- **해석 → 연구 질문.** 모델이 중요하다고 본 특징이 측정 장비의 특성이었다. 연구 질문이 장비 효과를 통제하도록 바뀐다.
- **데이터 → 연구 질문.** 필요한 데이터를 구할 수 없다. 질문을 데이터가 답할 수 있는 형태로 바꾼다.

되먹임은 실패가 아니라 정상적인 연구 과정이다. 다만 **되돌아간 기록을 남겨야 한다.** 테스트 결과를 본 뒤 분할을 바꾸고 다시 테스트했다면, 그 테스트 데이터는 더 이상 독립적인 측정이 아니다. 이 문제는 23.6장(결과 분석과 주장의 범위)에서 다시 다룬다.

:::note[직관]
실험 과학의 연구 과정과 비교하면 단계가 거의 그대로 대응한다. 가설을 세우고(연구 질문), 무엇을 측정할지와 대조군을 정하고(수학적 정의, baseline), 시료를 준비하고(데이터), 측정하고(학습·평가), 결과를 해석한다. ML 연구가 특별한 점은 "측정 장비"인 모델을 연구자가 직접 만들고 고친다는 것이다. 그래서 장비를 고치는 데 모든 시간을 쓰고 측정 설계를 잊기 쉽다.
:::

## 연구의 종류

**왜 종류를 구분하는가.** 같은 "모델 성능 향상"이라도 연구의 종류에 따라 기여의 의미와 검증 방법이 다르다. 자기 연구가 어느 종류인지 알아야 무엇을 증명해야 하는지 안다. 다른 사람의 논문을 읽을 때도, 그 논문이 무엇을 기여라고 주장하는지 먼저 파악해야 공정하게 평가할 수 있다.

| 종류 | 기여 | 무엇으로 검증하는가 | 예 |
|---|---|---|---|
| **알고리즘 연구** | 새 모델·학습법·추론법 | 여러 문제에서 강한 baseline과의 공정한 비교, ablation | 새로운 최적화 기법, 새로운 아키텍처 |
| **응용 연구** | 특정 문제를 풀어 현실의 결정을 개선 | 도메인 기준의 성공(실험 검증, 전문가 평가, 기존 방법 대비 비용) | 촉매 후보를 골라 실제 합성으로 확인 |
| **시스템 연구** | 더 크게·빠르게·싸게 돌리는 방법 | 같은 결과를 내는 데 드는 시간·메모리·비용 | 분산 학습, 추론 최적화 |
| **데이터·벤치마크 연구** | 문제를 정의하는 데이터와 평가 규칙 | 데이터 품질, 분할의 타당성, 기존 방법들의 순위가 현실과 맞는지 | 새 공개 데이터셋과 분할 규칙 |
| **분석 연구** | 현상의 이해 | 통제된 실험, 반례, 이론과의 일치 | 왜 어떤 모델이 외삽에 실패하는가 |

한 논문이 여러 종류를 겸할 수도 있다. 하지만 주된 기여가 무엇인지는 분명해야 한다. 응용 연구라고 주장하면서 검증은 알고리즘 연구처럼 벤치마크 점수로만 하면, 현실의 결정이 나아졌다는 근거가 빠진다.

::quiz{id="research-type"}

**벤치마크 성능과 현실 문제.** 벤치마크(benchmark)는 공개 데이터, 고정된 분할, 정해진 지표의 묶음이다. 벤치마크가 있으면 서로 다른 연구를 같은 기준으로 비교할 수 있어 분야가 빠르게 발전한다. 그러나 벤치마크 점수의 향상이 현실 문제의 해결로 이어지려면 두 조건이 필요하다.

1. **벤치마크의 분할이 현실의 일반화 대상과 같다.** 무작위 분할로 만든 벤치마크에서 1위인 모델이, 처음 보는 조건을 예측해야 하는 현실에서는 순위가 바뀔 수 있다.
2. **벤치마크의 지표가 현실의 비용과 맞다.** 평균 오차는 작지만 드물게 크게 틀리는 모델은, 큰 오차 한 번이 치명적인 현실에서는 쓸 수 없다.

같은 벤치마크로 오랫동안 많은 연구가 경쟁하면 또 하나의 문제가 생긴다. 각 연구가 테스트 점수를 보고 설계를 고르는 과정이 누적되어, 분야 전체가 그 테스트 데이터에 과적합될 수 있다. 벤치마크 점수의 작은 차이는 그래서 조심해서 읽는다(12.5장, 23.6장).

## 학습과 추론, 오프라인과 운영

**학습과 추론.** 모델의 생애에는 두 국면이 있다. **학습**(training)은 데이터로 파라미터 $\theta$를 정하는 과정이고, **추론**(inference)은 정해진 $\theta$로 새 입력 $x$에 대한 출력 $\hat{y} = f_\theta(x)$를 계산하는 과정이다. 두 국면은 조건이 다르다.

| | 학습 | 추론 |
|---|---|---|
| 이용 가능한 정보 | 입력과 정답 $(x, y)$의 모음 | 새 입력 $x$뿐(정답은 아직 없다) |
| 계산 | 반복적이고 무겁다(gradient 계산) | 한 번의 forward, 가볍다 |
| 빈도 | 몇 번(연구 중 재학습) | 많이(모든 새 입력마다) |
| 제약 | 총 계산 예산 | 지연 시간(latency), 장비의 메모리 |

여기서 가장 중요한 줄은 첫 줄이다. 학습 데이터에는 미래의 측정값이나 사후에 계산된 값이 섞여 있을 수 있지만, 추론 시점에는 그런 정보가 없다. 학습할 때 입력에 넣은 정보가 추론 시점에 존재하는지 확인하는 일은 1.3장에서 자세히 다룬다.

**오프라인 평가와 운영 환경.** 연구에서 하는 평가는 대부분 **오프라인 평가**(offline evaluation)다. 이미 모아 둔 데이터의 일부를 떼어 테스트 데이터로 두고, 학습이 끝난 모델의 점수를 잰다. 이 점수가 실제 사용 환경(운영 환경)에서의 성능을 대변하려면 테스트 데이터와 운영 환경의 데이터가 같은 분포에서 나와야 한다. 이 가정이 깨지는 방식은 여러 가지다.

- **분포 이동**(distribution shift). 장비가 바뀌거나, 계절이 바뀌거나, 새 재료를 다룬다. 학습·테스트 데이터에는 없던 조건이다(21.4장).
- **정답이 늦게 온다.** 배터리 수명은 수개월 뒤에야 알 수 있다. 운영 중에는 모델이 맞는지 바로 확인할 수 없다.
- **모델이 데이터를 바꾼다.** 모델이 고른 후보만 실험하면, 다음 학습 데이터는 모델이 좋다고 본 영역에 몰린다. 모델이 나쁘다고 본 영역은 다시 측정되지 않는다(25.3장, 25.4장).
- **입력 파이프라인이 다르다.** 연구 중에는 정제된 파일을 읽었지만, 운영에서는 결측과 단위 오류가 섞인 원시 데이터가 들어온다.

::quiz{id="offline-online-gap"}

:::note[분야 예시]
**기상 예측**: 과거 재분석 자료로 학습·평가한 예측 모델을 실제 예보에 쓰면, 입력이 재분석 자료가 아니라 실시간 관측에서 만든 초기장이 된다. 오프라인 평가의 입력과 운영의 입력이 다르다(27.4장). **실험실 자동화**: 모델이 추천한 조건만 실험하는 closed-loop 연구에서는, 모델이 처음에 놓친 영역이 끝까지 탐색되지 않을 수 있다(25.4장).
:::

이 간극은 연구 단계에서 없앨 수는 없지만 **줄이고 드러낼 수는** 있다. 운영 환경과 비슷하게 분할하고(시간 분할, 장비 분할), 조건별로 오차를 나눠 보고하고, 모델이 쓸 수 있는 범위를 명시한다.

## 제약과 절충

**왜 절충인가.** 연구에서 바라는 성질은 서로 부딪힌다. 정확도를 올리려면 계산과 데이터가 더 든다. 해석 가능성을 높이려면 모델을 단순하게 해야 하고, 그러면 정확도가 떨어질 수 있다. 모든 것을 최대로 할 수 없으므로, 어떤 성질을 얼마나 포기할지가 **설계 결정**이 된다.

| 성질 | 무엇으로 재는가 | 무엇과 부딪히는가 |
|---|---|---|
| 정확도 | 테스트 오차, 적정 점수 규칙(12.3장) | 계산량, 데이터 비용, 해석 가능성 |
| 계산량 | 학습 GPU 시간, 추론 지연 시간 | 정확도(큰 모델), 탐색 범위 |
| 데이터 비용 | 측정·시뮬레이션·label 비용 | 정확도, 일반화 범위 |
| 신뢰성 | 분포 이동에서의 성능, 불확실성의 calibration | 평균 정확도(강건하게 만들면 평균이 떨어지기도 한다) |
| 해석 가능성 | 사람이 모델의 근거를 검토할 수 있는가 | 정확도, 표현력 |

절충은 문제마다 다르게 풀린다. 같은 정확도라면 계산이 싼 쪽이 낫지만, "같은 정확도"의 기준이 무엇인지부터 정해야 한다. 과학 문제에서 흔한 판단 몇 가지를 든다.

- **대리모델**(surrogate model)은 정확도를 조금 포기하고 계산량을 크게 줄인다. 수천 번의 평가가 필요한 설계 탐색의 초기 단계에서는 이득이 크다. 최종 후보는 원래의 시뮬레이터나 실험으로 다시 확인한다.
- **물리 기반 모델**은 데이터 비용을 줄이고 해석 가능성을 높인다. 대신 물리 모델이 놓친 현상에서는 체계적으로 틀린다(24.5장).
- **불확실성 추정**은 계산량을 늘린다(앙상블은 모델 여러 개를 학습한다). 대신 어디서 모델을 믿지 말아야 하는지 알려 준다(21.1장).

::quiz{id="surrogate-tradeoff"}

:::tip[연구 팁]
연구를 시작할 때 각 성질에 대한 **최소 요구 수준**을 먼저 적는다. "추론은 1초 안에", "오차는 측정 잡음의 두 배 이내", "도메인 과학자가 근거를 검토할 수 있을 것". 요구 수준이 있어야 어떤 성질을 더 개선하는 것이 의미 있는지 판단할 수 있다. 요구 수준 없이 정확도만 올리다 보면, 이미 충분히 정확한 모델에 계산을 열 배 더 쓰게 된다.
:::

## 실습

관심 있는 논문 한 편을 골라 이 장의 아홉 단계로 분해하고, 단계별 결정과 가정을 한 장의 문서로 정리한다. 응용 연구 논문이면 가장 좋다. 이 문서는 23.2장(논문 읽는 법)과 23.3장(논문 재현)에서 다시 쓴다.

1. **논문의 종류를 정한다.** 다섯 종류 중 주된 기여가 무엇인지 쓰고, 그 종류에 맞는 검증이 논문에 있는지 확인한다.
2. **단계별 표를 채운다.** 아래 양식으로 아홉 단계의 산출물·결정·가정을 적는다. 논문에 명시되지 않은 가정은 "(추정)"으로 표시한다.

| 단계 | 논문의 산출물 | 내린 결정 | 숨은 가정 | 근거 위치 |
|---|---|---|---|---|
| 수학적 정의 | (예) 입력 32차원, 출력 스칼라 | (예) 출력을 로그 변환 | (예) 오차가 상대 오차로 의미 있다 (추정) | 2절 |
| 데이터 | | | | |
| … | | | | |

3. **가장 약한 가정 하나를 고른다.** 그 가정이 틀리면 결론이 어떻게 바뀌는지 두세 문장으로 쓴다. 예: "테스트 데이터가 학습과 같은 장비에서 측정되었다. 다른 장비에서는 오차가 커질 수 있으므로, 결론은 이 장비에 한정된다."
4. **되먹임 고리를 찾는다.** 논문 본문이나 부록에서 연구자가 앞 단계로 되돌아간 흔적(분할 변경, 지표 변경, 데이터 정제 기준 변경)이 있는지 찾는다. 없다면, 있었는데 적지 않았을 가능성도 메모한다.

## 실패 사례

- **모델 단계만 연구라고 생각하는 것.** 문제 정의와 데이터를 "준비 작업"으로 여기고 서둘러 넘기면, 잘못 정의된 문제에 좋은 모델을 맞추게 된다. 예를 들어 같은 시료의 반복 측정이 학습과 테스트에 나뉘어 들어간 데이터에서는 어떤 모델도 높은 점수를 받고, 모델 비교는 의미를 잃는다.
- **평가 단계를 마지막에 설계하는 것.** 모델을 다 만든 뒤에 평가 방법을 정하면, 이미 본 결과에 유리한 지표와 분할을 고르기 쉽다. 의도하지 않아도 그렇게 된다. 평가 단위·지표·성공 기준은 수학적 정의 단계(3단계)에서, 데이터를 보기 전에 정한다.
- **되돌아간 기록을 남기지 않는 것.** 테스트 점수를 본 뒤 전처리를 바꾸고 다시 테스트한 과정을 기록하지 않으면, 최종 점수가 몇 번의 시도 중 가장 좋은 것인지 아무도 알 수 없다. 연구 노트(23.7장)에 단계를 되돌아간 이유와 시점을 적는다.
- **벤치마크 1위를 현실 문제의 해결로 보고하는 것.** 벤치마크의 분할과 지표가 현실의 일반화 대상·비용과 같은지 확인하지 않으면, 순위는 그 벤치마크 안에서만 의미가 있다.

## 통과 기준

- 관심 논문 하나를 아홉 단계로 분해한 문서를 작성한다. 문서에는 논문의 종류, 단계별 산출물·결정·가정(명시되지 않은 것은 "(추정)" 표시), 가장 약한 가정과 그 가정이 틀렸을 때의 결론 변화가 들어 있다.
- 자신이 하려는(또는 하고 있는) 연구에서 평가 단위·지표·성공 기준을 데이터를 보기 전에 정해 문서에 적는다.
- 이 장의 개념 퀴즈를 모두 맞힌다.
