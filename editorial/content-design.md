## 1. 공통 예제

### 1.1 왜 공통 예제인가

장마다 새 예제를 쓰면 독자는 매번 문제 설정부터 다시 이해해야 한다. 같은 문제를 여러 장에서 반복해 다루면, 독자는 **같은 대상을 점점 더 깊은 도구로** 보게 된다. 선형대수에서 본 진동자를 확률로 다시 보고, 신경망으로 근사하고, PINN으로 풀고, 방정식 발견으로 법칙을 되찾는 식이다. 로드맵의 "나선형 학습"을 예제 수준에서 구현하는 방법이다.

### 1.2 선정 기준

| 기준 | 이유 |
|---|---|
| 여러 트랙을 관통한다 | 수학 → 통계 → ML → 과학 머신러닝 → 분야까지 한 예제로 이어져야 한다 |
| 정답을 안다 | 해석해나 정확한 시뮬레이션이 있어야 모델의 오류를 정량적으로 보여 줄 수 있다 |
| 브라우저에서 돈다 | NumPy만으로 몇 초 안에 생성·학습할 수 있어야 Pyodide 실습이 된다 |
| 실제 데이터의 함정도 보여 준다 | 합성 데이터만으로는 누수·결측·그룹 구조·검열을 가르칠 수 없다 |
| 공개·재배포 가능 | 오픈소스 책이므로 라이선스가 재배포를 허용해야 한다 |
| 분야 중립적이다 | 특정 분야 독자만 이해하는 예제는 공통 예제가 될 수 없다 |

### 1.3 제안: 세 개의 실(thread)

| | 실 1. 감쇠 진동자 | 실 2. 열 방정식 | 실 3. 실제 측정 데이터 |
|---|---|---|---|
| 대상 | $\ddot{x} + 2\zeta\omega\dot{x} + \omega^2 x = 0$ (질량–스프링–감쇠기) | $\partial_t u = \kappa\,\partial_{xx} u$ (1차원, 이후 2차원) | 공개 배터리 사이클 데이터 (셀별 용량·전압·전류·온도) |
| 성격 | 시간에 따른 **상태**, 해석해 있음 | 공간을 가진 **장(field)**, 해석해·수치해 있음 | **지저분한 실제 데이터**: 그룹(셀)·시간·결측·검열·조건 차이 |
| 데이터 | 브라우저에서 생성 | 브라우저에서 생성 | 내려받기(라이선스 확인 후 소규모 발췌본 동봉) |
| 가르치는 것 | 동역학, 파라미터 추정, 불확실성, 물리 기반 학습, 법칙 발견 | 이산화, 함수공간, 연산자 학습, 역문제, 확산과 가우시안 | 데이터 의미, 분할과 누수, 기준 모델, 시계열, 수명·검열, 분포 이동, 신뢰성 |

**왜 이 셋인가**

- **감쇠 진동자**는 과학 머신러닝을 가르칠 때 흔히 쓰이는 예제다. 2차원 선형 시스템이라 고윳값으로 거동(과감쇠·임계감쇠·부족감쇠)이 완전히 설명되고, 잡음을 섞으면 통계·베이지안 추론의 예제가 되며, PINN·Neural ODE·방정식 발견의 기준 문제로 바로 이어진다. 물리·화학·생명·공학 어느 분야 독자에게도 낯설지 않다.
- **열 방정식**은 공간 차원이 있는 가장 단순한 PDE다. 유한차분과 안정성 조건(CFL), Fourier 기저(함수공간), neural operator, 역문제(전도도 추정)를 한 예제로 가르칠 수 있다. 열 방정식의 해가 가우시안 커널과의 합성곱이라는 사실은 확률(가우시안)과 확산 생성모델을 잇는 다리가 된다.
- **실제 측정 데이터**가 없으면 데이터 트랙(15부)과 신뢰성 트랙(21부)의 핵심 — 그룹 분할, 미래 정보 누수, 검열, 측정 조건에 따른 분포 이동 — 을 실감할 수 없다. 배터리 사이클 데이터는 이 함정이 모두 들어 있고, 셀이라는 명확한 그룹 단위가 있으며, 30부(에너지·배터리)로 자연스럽게 이어진다. 데이터셋별 라이선스·상업적 이용 여부를 함께 제공하는 통합 스키마 허브(예: BatangHub)를 후보 선정에 활용할 수 있다.

분야별 부(26–30부)는 각 분야의 고유 데이터를 쓴다. 공통 예제는 1–25부의 공통 언어다.

## 2. 분량과 깊이

| | 필수(core) | 심화(advanced) | 참조(reference) |
|---|---|---|---|
| 개념 절 | 3–6개 | 3–6개 | 2–4개 |
| 수학 수준 | 학부 미적분·선형대수 기초를 가정. 연구 판단에 필요한 결과는 유도 | 유도 + 핵심 정리의 증명 스케치 | 결과와 사용법 |
| 예제 | 절마다 1개 이상, 공통 예제 우선 | 절마다 1개 이상 | 사용 예 |
| 위젯 | 0–2개 (이해가 빨라지는 곳에만) | 0–2개 | 없음 |
| 코드 셀 | 2–5개 | 2–5개 | 필요 시 |
| 퀴즈 | 5–8문항 (목표마다 1개 이상) | 3–5문항 | 선택 |
| 실습 | 1개 이상 + 자동 채점 연습문제 1–3개 | 1개 | 선택 |
| 학습 시간 | 읽기 30–60분 + 실습 60–120분 | 읽기 45–90분 + 실습 | 15–30분 |

- 증명 정책: 독자가 결과를 **언제 믿어도 되는지** 판단하는 데 필요한 경우만 증명한다. 그 밖에는 직관과 참고 자료로 대신한다.
- 장이 위 범위를 넘으면 장을 나누는 것을 먼저 검토한다(한 장 = 한 학습 단위).

## 3. 두 독자를 위한 설명

이 로드맵의 독자는 'AI를 배우는 과학자'와 '과학을 배우는 AI 연구자'다. 한쪽에게 당연한 것이 다른 쪽에게는 낯설다.

- 본문은 두 독자 모두를 기준으로 쓴다. 한쪽 분야의 관행을 쓸 때는 처음 등장할 때 정의한다.
- 한쪽 독자에게만 필요한 연결 설명은 **다리 상자**로 분리한다. 필요 없는 독자는 건너뛴다.

```md
:::note[과학자를 위해]
ML에서 "검증 데이터"는 실험의 재현 측정이 아니라, 모델 선택에만 쓰고 최종 보고에는 쓰지 않는 데이터다.
:::

:::note[AI 연구자를 위해]
stiff한 ODE는 시간 척도가 크게 다른 현상이 섞인 방정식이다. 명시적 방법은 가장 빠른 척도에 맞춰 step을 줄여야 한다.
:::
```

- 다리 상자는 장당 2–4개를 넘지 않게 한다. 많아지면 그 내용은 본문이나 선수 장으로 옮긴다.

## 4. 표기법

[부록 A. 표기법](../content/appendices/a-notation/index.md)을 본문보다 먼저 완성한다. 기준:

| 대상 | 표기 | 예 |
|---|---|---|
| 스칼라 | 이탤릭 소문자 | $x, \alpha$ |
| 벡터 | 굵은 소문자, 열벡터 | $\mathbf{x} \in \mathbb{R}^d$ |
| 행렬 | 굵은 대문자 | $\mathbf{A}, \mathbf{W}$ |
| 확률변수 | 대문자 | $X, Y$ |
| 분포·밀도 | $p(\cdot)$, 매개변수는 아래첨자 | $p_\theta(y \mid x)$ |
| 데이터셋 | 필기체 | $\mathcal{D} = \{(\mathbf{x}_i, y_i)\}_{i=1}^N$ |
| 기댓값·분산 | | $\mathbb{E}[X], \operatorname{Var}[X]$ |
| 정규분포 | | $\mathcal{N}(\boldsymbol{\mu}, \boldsymbol{\Sigma})$ |
| 미분 | gradient는 열벡터, Jacobian은 (출력 × 입력) | $\nabla_\theta L, \ \mathbf{J} \in \mathbb{R}^{m \times n}$ |
| 시간 | 연속 $t$, 이산 단계 $k$ | $\mathbf{x}(t), \mathbf{x}_k$ |
| 물리량 | SI 단위, 코드에서는 단위 접미사 | `current_a`, `temp_c` |

- **분야 간 충돌:** 같은 기호가 분야마다 다른 뜻을 가지면(예: 제어에서 $\mathbf{x}$는 상태, ML에서는 입력) 그 장의 첫머리에 **지역 표기 상자**를 두고 부록 A와 다른 점만 적는다.

## 6. 장 명세 (목차와 본문 사이)

현재 장 파일은 "상세 목차"다. 본문을 바로 쓰는 대신 **장 명세** 단계를 거친다. 명세는 장당 한 쪽 분량이라 방향을 빨리 검토할 수 있다.

장 상태에 `spec`을 추가한다: `outline` → **`spec`** → `draft` → `review` → `done`.

절마다 다음을 적는다(형식: [templates/chapter-spec.md](../templates/chapter-spec.md)).

| 항목 | 내용 |
|---|---|
| 핵심 메시지 | 이 절을 읽고 남아야 할 한 문장 |
| 설명 순서 | 왜 필요한가 → 정의 → 직관 → 수식 → 코드 → 연구에서의 의미 중 실제로 쓸 단계와 요점 |
| 예제 | 공통 예제(실 1–3) 또는 절 고유 예제 |
| 시각화·위젯 | 그림, 위젯 이름과 프리셋, 효과(design-system.md §5) |
| 코드 | 코드 셀의 목적과 `exec` 수준 |
| 예측 퀴즈 | 절 앞에 놓을 질문과 흔한 오답 |
| 흔한 오개념 | 실패 사례로 연결할 착각 |
| 참고 | 근거 문헌 |

명세가 승인되면 `write-chapter` skill이 명세를 바탕으로 본문을 쓴다.
