# 로드맵 설계 근거

이 문서는 [OUTLINE.md](../OUTLINE.md)의 **트랙·레이어·평가 구조가 왜 이렇게 생겼는지** 기록한다.
트랙 정의의 원천은 [`book.toml`](../book.toml)이고, 아래 규칙 중 기계적으로 검사할 수 있는 것은 모두 `scripts/book.py check`가 검사한다.

## 0. 이 로드맵의 목적

**AI for Science 오픈소스 로드맵.** 과학 문제를 AI로 정의하고, 검증하고, 재현 가능하게 전달하는 연구자가 되기 위한 경로를 누구나 읽고, 실행하고, 고치고, 기여할 수 있게 공개한다.

주된 독자는 두 갈래다.

| 독자 | 이미 가진 것 | 채워야 할 것 | 출발점 |
|---|---|---|---|
| **AI를 배우는 과학자·공학자** | 분야 지식, 실험·시뮬레이션 경험, 수학 일부 | 연구 소프트웨어, ML 핵심, 평가와 누수, 불확실성 | RSE → MLC |
| **과학을 배우는 AI 연구자** | ML·딥러닝, 코드 | 수치해석, 확률적 추론, 물리 기반 모델, 분야의 데이터와 평가 기준 | MTH(수치해석) · PSI → SML → DOM |

두 독자는 **과학 머신러닝(SML)**에서 만난다. 그래서 SML이 분야별 응용(DOM) 바로 아래 레이어에 있다.

## 1. 로드맵의 두 축

| 축 | 질문 | 정하는 것 | 데이터 |
|---|---|---|---|
| **레이어 × 트랙** (구조) | 무엇이 무엇에 기대는가? | 트랙 사이의 의존 방향, 책의 부 순서 | `book.toml`의 `layers`·`tracks`, 장의 `prerequisites` |
| **단계** (경로) | 언제 무엇을 배우는가? | 개인의 학습 순서, 단계별 종합 프로젝트 | 학습 경로(0.3장), 종합 프로젝트(31.1장) |

두 축을 섞지 않는다. 수학(L1)은 딥러닝(L2)보다 **아래 레이어**지만, 학습자는 나선형 경로를 따라 **1단계에서 딥러닝 학습 루프를 먼저 얕게 경험**하고 2단계에서 그 수학을 깊이 배운다.
레이어는 "깊이 이해하려면 무엇이 먼저 필요한가"이고, 단계는 "언제 처음 만나는가"다.

## 2. 레이어와 트랙

```
L6 통합    │ CAP 종합 프로젝트
───────────┼─────────────────────────────────────────────────────────────
L5 응용    │ DOM 과학 분야별 응용  (물리·공학 · 지구·기후 · 화학·재료 · 생명과학 · 에너지·배터리)
───────────┼─────────────────────────────────────────────────────────────
L4 방법론  │ RES 연구 방법론          SML 과학 머신러닝
───────────┼─────────────────────────────────────────────────────────────
L3 확장    │ MLA 머신러닝 심화        MLS 머신러닝 시스템
───────────┼─────────────────────────────────────────────────────────────
L2 핵심    │ MLC 머신러닝 핵심
───────────┼─────────────────────────────────────────────────────────────
L1 기반    │ INF 연구 인프라  RSE 연구 소프트웨어 공학  MTH 수리 기초  PSI 확률·통계적 추론
───────────┼─────────────────────────────────────────────────────────────
L0 입문    │ ORI 오리엔테이션
           │                                                 REF 참고 자료 (레이어 밖)
```

| 레이어 | 의미 | 트랙 |
|---|---|---|
| **L0 입문** | 어떤 선수 지식도 요구하지 않는 출발점. AI for Science의 지형 포함 | `ORI` |
| **L1 기반** | 서로 병행해 배우는 네 기반 역량. 다른 기반 트랙에만 기댄다 | `INF` `RSE` `MTH` `PSI` |
| **L2 핵심** | 기반을 결합해 학습 시스템 전체를 다루는 역량 | `MLC` |
| **L3 확장** | 핵심 위에서 모델링의 **폭**(MLA)과 실험의 **규모**(MLS)를 넓힌다 | `MLA` `MLS` |
| **L4 방법론** | ML을 **연구 방법**(RES)과 **과학적 모델링의 방법**(SML)으로 확장한다 | `RES` `SML` |
| **L5 응용** | 방법론을 과학 분야별 데이터·문제·평가 기준에 적용한다 | `DOM` |
| **L6 통합** | 여러 트랙을 하나의 공개 연구 산출물로 묶고 커뮤니티에 기여한다 | `CAP` |

### 2.1 기반 레이어가 네 트랙인 이유

책의 네 축(이론·구현·연구·운영) 중 연구를 뺀 세 축이 기반에서 갈라진다.

| 축 | 기반 트랙 | 구분의 근거 |
|---|---|---|
| 운영 | `INF` 연구 인프라 | 대상이 **실행 환경**(서버·드라이버·패키지·컨테이너·Git). 평가는 터미널 실습 |
| 구현 | `RSE` 연구 소프트웨어 공학 | 대상이 **코드 자체**(언어·구조·설정·테스트). 평가는 코드 실습과 리뷰 |
| 이론 | `MTH` 수리 기초 | **결정론적 계산의 수학**: 공간(선형대수·대칭)·변화(미적분)·근사(수치해석)·최적화 |
| 이론 | `PSI` 확률·통계적 추론 | **불확실성의 수학**: 확률·추정·베이지안·정보와 일반화 |

AI for Science에서 수치해석(9부)과 확률적 추론(11–14부)이 일반 ML 커리큘럼보다 두껍다. 시뮬레이터는 데이터 생성기이자 baseline이자 오차의 원천이고, 과학적 결론에는 불확실성이 따라야 하기 때문이다.

### 2.2 확장 레이어가 두 트랙인 이유

`MLA`(생성모델·강화학습·신뢰성)는 **무엇을 모델링하는가**를 넓히고, `MLS`(실험 추적·재현성·profiling·분산학습)는 **얼마나 크고 믿을 수 있게 돌리는가**를 넓힌다. 둘 다 MLC 위에 있지만 서로 기대지 않는다.

### 2.3 방법론과 응용을 나눈 이유

- `SML` 과학 머신러닝(24–25부)은 **분야를 가로지르는 방법**이다: 물리 기반·하이브리드 모델, neural operator, 역문제와 UQ, 대칭성을 반영한 모델, 시뮬레이션 기반 추론, 방정식 발견, 실험 설계와 자율 실험.
- `DOM` 과학 분야별 응용(26–30부)은 **분야마다 다른 것**을 다룬다: 데이터가 만들어지는 과정, 표준 평가 지표, 분야 특유의 누수(화학의 유사 구조, 생명과학의 서열 유사성, 기상의 면적 가중·흐릿함).
- 분야별 부는 같은 뼈대를 따른다: **ML 연구자를 위한 분야 기초 → 데이터 → 대표 문제와 모델 → 평가와 함정.** 새 분야(천문, 고에너지 물리, 신경과학 등)를 기여받을 때도 이 뼈대를 쓴다.
- 에너지·배터리(30부)는 다른 분야보다 깊게, 앞의 거의 모든 트랙을 한 분야에 통합하는 **사례 연구**로 둔다.

### 2.4 근거: 실제 선수 지식 그래프

레이어는 선언이 아니라 **장들의 `prerequisites`에서 집계한 트랙 간 의존**과 일치해야 한다. 집계 결과는 OUTLINE.md의 "트랙 간 의존" 표에 자동으로 생성되며, 다음 두 규칙을 `check`가 강제한다.

1. **레이어 단조성:** 모든 장의 선수 지식은 같은 레이어 또는 더 낮은 레이어의 트랙에 있다.
2. **트랙 비순환:** 트랙 단위로 집계한 의존 그래프에 순환이 없다(같은 레이어 안에서도).

이 두 규칙 덕분에 로드맵은 항상 아래에서 위로 읽히고, 책의 부 순서(트랙 순서 = 레이어 순서)도 같은 방향을 따른다. 장을 추가하거나 선수 지식을 바꿨을 때 이 규칙이 깨지면 **트랙 배치가 틀렸거나 선수 지식이 틀린 것**이다.

## 3. 트랙 이름 규칙

| 요소 | 규칙 | 예 |
|---|---|---|
| `key` | 영어 kebab-case. frontmatter `track` 값이자 URL 경로. 바꾸지 않는다 | `research-software-engineering` |
| `code` | 영문 대문자 3자. UI 배지·짧은 참조. 영어 이름의 머리글자에서 따온다 | `RSE` |
| `name` | 한국어 **분야명**(명사구). "~하기", "~의 기초" 같은 서술형을 쓰지 않는다 | 연구 소프트웨어 공학 |
| `name_en` | 학계·산업에서 **실제로 통용되는 분야명**. 새로 만들지 않는다 | Research Software Engineering |
| `question` | 트랙이 답하는 핵심 질문 하나 | 수식과 아이디어를 어떻게 정확하고 유지 가능한 코드로 옮기는가? |
| `outcome` | "~한다"로 끝나는 도달 목표. 관찰 가능한 행동 | 설정·CLI·테스트·문서를 갖춘 연구 프로젝트를 만들고 협업한다 |

계층을 나타내는 말은 머신러닝 트랙에만 일관되게 쓴다: **핵심**(Core) → **심화**(Advanced) → **시스템**(Systems).
`Research Software Engineering`, `Machine Learning Systems`, `Probabilistic and Statistical Inference`, `Scientific Machine Learning`, `Capstone Projects`는 모두 해당 분야·교육 과정에서 쓰는 이름이다.

## 4. 평가 체계

트랙마다 **주된 평가 방식**이 다르다. 코드 실습이 없는 장(오리엔테이션·연구 방법론·수학 일부·분야 기초)은 개념 퀴즈와 문서 산출물로 통과를 확인한다. 서비스는 로그인 없는 오픈소스이므로 모든 채점은 학습자 쪽에서 이루어지고, 정답·테스트·해답은 공개된다.

| 평가 방식 | 수단 | 채점 | 주로 쓰는 트랙 |
|---|---|---|---|
| `quiz` 개념 퀴즈 | 장의 `quiz.toml` — 단일 선택·복수 선택·수치 입력 | 브라우저 즉시 채점 | ORI · MTH · PSI · RES · SML · DOM (+ 모든 트랙 보조) |
| `code` 코드 실습 | 학습자의 브라우저(Pyodide) 또는 로컬 Python 런타임에서 실행, 공개 테스트 | 자동 | RSE · MTH · PSI · MLC · MLA · MLS · SML · DOM |
| `terminal` 터미널 실습 | 학습자 자신의 터미널에서 수행, 검사 스크립트 | 자동 | INF · MLS |
| `document` 문서 산출물 | 문제 정의서·실험 계획서·재현 보고서·데이터 카드 템플릿 | 루브릭 + 자기 점검 | ORI · RES · DOM · CAP |
| `review` 동료 리뷰 | 코드·실험·발표 리뷰 (스터디·커뮤니티·지도교수) | 사람 | RSE · RES · CAP |

### 4.1 퀴즈를 쓰는 원칙

- 모든 문항은 장의 **학습 목표 하나**에 연결된다(`objective`). 학습 목표와 무관한 지식 확인 문항은 쓰지 않는다.
- 암기가 아니라 **오개념을 드러내는** 문항을 쓴다. 오답 선택지는 실제로 자주 하는 착각이어야 하고, 각 오답에 `feedback`을 단다.
- 모든 문항에 `explanation`(왜 정답인가)을 쓴다. 퀴즈는 시험이 아니라 학습 도구다.
- 수치 입력 문항은 손으로 계산 가능한 크기로 낸다.
- 본문 중간에 `::quiz{id="..."}`로 한 문항을 삽입해 **예측해 보기**(읽기 전에 답하고, 위젯·코드로 확인)에 쓴다.

### 4.2 트랙 졸업 과제와 종합 프로젝트

트랙마다 `capstone`이 있다(OUTLINE.md 트랙 머리 참고). 트랙의 모든 필수 장 통과 기준 + 졸업 과제 = 트랙 이수.
31.1장의 단계별 종합 프로젝트(A–H)는 **여러 트랙을 가로지르는** 과제이고, 트랙 졸업 과제는 **한 트랙 안의** 과제다.

## 5. 변경 이력

### 5.1 초안(ChatGPT 답변)에서 바꾼 것

출발점이었던 "20개 대분류·80개 장" 초안의 좋은 점 — 네 축 병행, 장의 공통 형식, 필수·심화·참조, 목차 순서와 학습 순서의 분리, 산출물 기반 진도 — 은 그대로 가져왔다. 바꾼 것은 다음과 같다.

1. **트랙·레이어 도입.** 평평한 20개 부 대신, 검증 가능한 의존 규칙을 가진 7개 레이어·12개 트랙(+참고).
2. **작업대를 앞으로.** 입문자가 처음 막히는 곳은 수학이 아니라 서버와 환경이다. INF·RSE를 L1에 두고 부 번호도 앞에 배치했다.
3. **첫 파이프라인 장(1.5)** — 나선형 학습의 진입점.
4. **요청 주제를 독립 장으로:** 아핀 구조와 비선형성(7.2), rank(7.3), 다양체(7.8), 분포 기반 문제 정의(12.3), 학습 루프 해부(17.5), Ubuntu·CUDA(3.2), venv·uv·conda(3.3), 에이전트 지침(4.4), MCP(4.5), 실행 위치의 지도(2.4), 프로젝트 구조(6.1), 설정 관리(6.3), CLI(6.4), 대시보드(17.8).
5. **보강:** 텐서와 einsum(7.7), 함수공간(7.9), 2차 최적화(10.5), 베이지안 최적화(10.7), 다변량 가우시안(11.4), 확률과정·SDE(11.7), Gaussian process(13.7), 스케일링 법칙(14.5), LLM 기초(18.5), flow matching(19.6), 강화학습 부(20부), conformal prediction(21.3), GPU 메모리(22.5), 연구 방법론 4장 → 13장.
6. **수치해석을 독립 부로**(9부).

### 5.2 연구실 교육용에서 AI for Science 오픈소스 로드맵으로

1. **연구실 운영 트랙(LAB) 삭제.** handbook·공통 자산·리뷰 체계·인수인계는 특정 조직의 운영 문제다. 종합 프로젝트와 역량 평가는 `CAP` 종합 프로젝트(31부)로 옮기고, 오픈소스·데이터·벤치마크 기여(31.2) 장을 추가했다.
2. **도메인 트랙을 방법론(SML)과 응용(DOM)으로 분리.** 배터리 한 분야였던 응용을 물리·공학(26부), 지구·기후(27부), 화학·재료(28부), 생명과학(29부), 에너지·배터리(30부)로 넓혔다.
3. **과학적 발견과 실험 설계(25부) 신설:** 시뮬레이션 기반 추론, 방정식 발견, 능동 학습과 베이지안 실험 설계, 자율 실험, 과학 foundation model과 에이전트.
4. **과학 특화 기반 장 추가:** AI for Science의 지형(1.2), 대칭과 군 표현(7.10), 대칭성을 반영한 과학 모델(24.8), 도메인 과학자와의 협업(23.13).
5. **독자 재정의:** 연구실 신입 연구원 → AI를 배우는 과학자와 과학을 배우는 AI 연구자. 세미나 운영 장은 스터디·강의 활용 장(0.5)으로 바꿨다.

## 6. 유지할 원칙

1. **한 장 = 한 학습 단위.** 장이 두 목표를 가지면 나눈다.
2. **모든 장은 산출물로 끝난다.** 통과 기준이 "이해한다"로 끝나면 다시 쓴다.
3. **선수 지식은 최소로.** 꼭 필요한 직전 장만 적는다. 단, 트랙을 넘는 의존은 빠뜨리지 않는다 — 로드맵의 근거가 되기 때문이다.
4. **필수(core)는 모든 독자가 직접 할 수 있어야 하는 것만.** 현재 215장 중 149장 — 집필하며 심화로 내릴 후보를 검토한다. 분야별 부(DOM)는 독자가 고른 분야에서만 필수다.
5. **도구는 개념과 절차로 가르치고, 버전·화면은 갱신되는 참조로 둔다.**
6. **분야별 부는 같은 뼈대를 따른다.** 분야 기초 → 데이터 → 대표 문제와 모델 → 평가와 함정.

## 7. 열린 질문

- 1단계 필수 경로를 40–50장으로 별도 정의할 것인가? (학습 경로를 데이터 파일 `paths/*.toml`로 만들어 독자 유형·단계별 장 목록과 종합 프로젝트를 관리하는 안)
- 분야별 부의 `tier`를 "그 분야를 고른 독자에게 필수"로 표현하는 방법 (예: 학습 경로 파일에서 분야별로 필수 지정)
- 영어판을 낼 것인가? 오픈소스 AI for Science 독자는 국제적이다. 낸다면 i18n 디렉터리 구조를 사이트 구축 전에 정한다.
