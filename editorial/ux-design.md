# UI/UX 설계 노트 (논의 중)

> 상태: **초안 — 결정 전.** 이 문서는 선택지를 정리하고 결정해야 할 질문을 모은다. 결정이 나면 "결정 기록" 절에 남긴다.

## 1. 이 책의 UX가 풀어야 할 문제

일반적인 기술 문서와 다른 점이 세 가지 있다.

1. **분량이 크고 순서가 하나가 아니다.** 190개 장을 처음부터 읽는 독자는 없다. 독자는 "지금 내게 필요한 장"과 "그 장을 읽기 전에 필요한 것"을 찾아야 한다. → **지도와 경로**가 핵심 내비게이션이다.
2. **읽는 책이 아니라 훈련하는 책이다.** 각 장은 실습과 통과 기준으로 끝난다. → **진행도**와 **산출물 확인**이 UI에 드러나야 한다.
3. **수식·코드·그림이 함께 간다.** 같은 개념을 수식과 코드로 오가며 읽어야 한다. → **수식–코드 대응**을 보여 주는 레이아웃이 필요하다.

## 2. 독자 시나리오

| 독자 | 상황 | 필요한 UI |
|---|---|---|
| 신입 연구원 | 첫 주, 무엇부터 할지 모름 | 학습 경로 선택 → 단계별 장 목록 → 진행도 |
| 2년 차 연구원 | 논문에서 ELBO가 나와 막힘 | 검색(한·영) → 장 → 선수 지식 카드로 거슬러 올라가기 |
| 지도교수·선배 | 세미나 진도 확인, 리뷰 | 장별 통과 기준, 연구실 공유 진행도(선택) |
| 외부 독자 | 검색으로 한 장만 방문 | 장 단독으로 읽히는 구성, 장 머리의 맥락 카드 |

## 3. 정보 구조

```
홈 ─ 로드맵 지도(트랙 × 부, 선수 지식 그래프)
 ├─ 학습 경로 (1–5단계, 배경별 경로, 도메인 트랙 A/B/C)
 ├─ 트랙 → 부 → 장 → (절)
 ├─ 부록: 표기법 · 용어집 · 공식 · 치트시트 · 실패 사례 갤러리 · 템플릿 · 체크리스트
 └─ 검색
```

- 사이드바는 **트랙별 색**으로 구분하고, **등급 필터**(필수만 / 필수+심화 / 전체)를 둔다.
- 각 장은 `prerequisites`로 연결되어 있으므로, **역방향 링크**("이 장을 선수로 하는 장")를 자동 생성할 수 있다.

## 4. 장 페이지의 해부도

```
┌─────────────────────────────────────────────────────────────┐
│ 7.2 · 선형대수와 기하                    [필수] [초고] 트랙색 │  ← 메타 바
│ 아핀 구조와 비선형성                                          │
│ Affine Structure and Nonlinearity                            │
├──────────────────────────────────┬──────────────────────────┤
│ ┌ 선수 지식 ──────────────────┐  │ 이 페이지                  │
│ │ ✓ 7.1 벡터공간과 선형사상    │  │  · 학습 목표               │
│ └──────────────────────────────┘ │  · 선형 변환과 아핀 변환    │
│ ┌ 학습 목표 ──────────────────┐  │  · ...                     │
│ │ • Ax와 Ax+b의 차이를 설명한다 │  │  · 실습                    │
│ └──────────────────────────────┘ │  · 통과 기준               │
│                                  │                            │
│ 본문 (정의 → 직관 → 수식 → 코드)   │ 진행도 ▓▓▓░░ 3/5          │
│  [수식 | 코드] 나란히 보기         │                            │
│  [인터랙티브: 평면 변형 시각화]    │                            │
│                                  │                            │
│ ┌ 실습 ───────── labs/... ▶ ──┐  │                            │
│ ┌ 실패 사례 ⚠ ─────────────────┐ │                            │
│ ┌ 통과 기준 ☐ ─────────────────┐ │                            │
│ │ ☐ 증명과 그림으로 설명한다    │  │                            │
│ └──────────────────────────────┘ │                            │
│ 다음으로: 7.3 rank · 이 장이 필요한 장: 17.1, 18.1              │
└─────────────────────────────────────────────────────────────┘
```

고정 제목 절(`학습 목표 · 실습 · 실패 사례 · 통과 기준`)은 빌드 시 전용 컴포넌트로 변환한다. 그래서 저자는 순수 Markdown만 쓴다.

## 5. 컴포넌트 후보

| 컴포넌트 | 데이터 원천 | 우선순위 |
|---|---|---|
| 메타 바(번호·등급·상태·트랙) | frontmatter + book.toml | 1 |
| 선수 지식 카드 | `prerequisites` | 1 |
| 학습 목표 / 실습 / 실패 사례 / 통과 기준 박스 | 고정 제목 절 | 1 |
| 콜아웃(직관·연구 팁·함정·배터리 예시·심화) | `:::` 컨테이너 | 1 |
| 로드맵 지도(그래프·노선도) | 전체 `prerequisites` | 2 |
| 역방향 링크 | 전체 `prerequisites` | 2 |
| 용어 툴팁(한·영) | `data/glossary.toml` | 2 |
| 수식–코드 나란히 보기 | MDX 컴포넌트 | 2 |
| 통과 기준 체크리스트 + 진행도 | 브라우저 저장(로컬) | 3 |
| 인터랙티브 위젯(선형변환, 경사하강, 분포 등) | 컴포넌트(아일랜드) | 3 |
| 연구실 공유 진행도 | 계정·DB 필요 | 선택 |
| 장/책 PDF | 별도 빌드 | 4 |

## 6. 시각 디자인 방향

- **타이포그래피:** 본문 한글 산세리프(예: Pretendard), 코드 고정폭(예: JetBrains Mono, D2Coding), 수식 KaTeX. 한글 본문은 줄간격 1.7–1.8, 한 줄 폭 약 36–40자(한글 기준)로 긴 글 읽기에 맞춘다.
- **색:** 트랙 7개 + 부록을 구분하는 절제된 팔레트. 의미 색(경고·팁)은 트랙 색과 겹치지 않게. 라이트·다크 모두 대비 기준 충족.
- **밀도:** 교과서처럼 여백이 넉넉하게. 사이드바·목차는 접을 수 있게.
- **그림:** 가능한 SVG. 라이트·다크 모드에서 모두 읽히도록 색을 토큰으로.

## 7. 프레임워크 선택지

본문을 프레임워크 중립적인 Markdown(+ `:::` 컨테이너, `$` 수식)으로 쓰고 있으므로 아래 어느 쪽으로도 옮길 수 있다.

| 후보 | 강점 | 약점 | 적합한 경우 |
|---|---|---|---|
| **Astro Starlight** | 빠른 정적 사이트, MDX와 컴포넌트 아일랜드로 인터랙티브 위젯 자유, 내장 검색(Pagefind), `:::` 콜아웃 기본 지원, i18n | 인쇄·PDF는 별도 파이프라인 필요, 코드 실행 없음 | **웹 경험이 1순위**, 커스텀 컴포넌트가 많음 |
| **Docusaurus** | 성숙한 React 생태계, 버전 관리, 플러그인 많음 | 무겁고 커스터마이징 비용 큼 | 버전별 문서가 필요할 때 |
| **Quarto Book** | 같은 원천에서 HTML·PDF·EPUB, 코드 실행 결과 포함, 교차 참조·수식 번호 강력 | 인터랙티브 UI 확장성 낮음, 콜아웃 문법이 다름 | **인쇄 출판이 1순위**, 실행 가능한 노트북 |
| **MyST / Jupyter Book 2** | 과학 출판 지향, 실행 가능, 교차 참조 | 생태계 전환기, 커스텀 UI 제약 | 노트북 중심 교재 |
| **MkDocs Material** | 설정만으로 깔끔한 문서 | 생태계 전환기(후속 도구로 이행 중), 확장 한계 | 빠르게 공개만 할 때 |
| **VitePress** | 가볍고 빠름 | 커스텀 데이터 처리 직접 구현 | 소규모 문서 |

**잠정 권장:** *웹 우선 + 인쇄 대비* 구조.

- 웹: **Astro Starlight** — 로드맵 지도·진행도·위젯 같은 이 책 고유의 UX를 구현하기 가장 자유롭다.
- 인쇄: 같은 `content/`에서 **Pandoc 또는 Typst** 파이프라인으로 PDF 생성(4단계에서).
- 인쇄본이 웹만큼 중요하다면 처음부터 **Quarto**를 택하는 편이 낫다 — 아래 질문 2에 따라 결정.

## 8. 단계별 계획

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 | 본문 규칙 확정, 목차 작성 (**현재**) | `check` 통과, OUTLINE.md |
| 1 | 기본 테마로 사이트 구동, 사이드바·검색·수식·다크모드 | 모든 장이 렌더링, CI 배포 |
| 2 | 메타 바·선수 지식 카드·고정 절 박스·콜아웃·역방향 링크 | 장 페이지 해부도 구현 |
| 3 | 로드맵 지도·학습 경로·진행도·용어 툴팁·첫 인터랙티브 위젯 | 신입 연구원 사용성 테스트 |
| 4 | PDF/인쇄 파이프라인, (선택) 연구실 공유 진행도 | 장별·전체 PDF |

## 9. 결정이 필요한 질문

1. **공개 범위:** 공개 웹(검색 노출) / 연구실 내부 전용 / 일부 공개 후 출판?
2. **인쇄본의 비중:** 종이책·PDF 출판이 웹만큼 중요한가? (→ Starlight vs Quarto)
3. **코드 실행:** 본문에 실행 결과를 빌드 시 자동 삽입해야 하는가, 아니면 `labs/` 링크로 충분한가?
4. **진행도:** 개인 브라우저 저장으로 충분한가, 연구실 단위로 공유·확인해야 하는가?
5. **언어:** 영어판 계획이 있는가? (있다면 i18n 디렉터리 구조를 1단계에서 정한다)
6. **디자인 톤:** 교과서형(차분·여백) / 개발 문서형(정보 밀도) / 인터랙티브 코스형(카드·진행도 중심) 중 어느 쪽?
