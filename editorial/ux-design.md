# UI/UX 설계

> 상태: **채택** ([ADR 0010](decisions/0010-reference-based-design.md), 2026-11-06). 이전 판(테마·dock·효과·위젯 종류·스크롤 연동 모션)은 폐기했다.
> 시각 토큰과 컴포넌트는 [design-system.md](design-system.md), 레퍼런스 조사는 [benchmarks.md](benchmarks.md), 시스템 구조는 [platform-architecture.md](platform-architecture.md)를 본다.

## 1. 이 서비스의 UX가 풀어야 할 문제

1. **분량이 크고 순서가 하나가 아니다.** 215개 장을 처음부터 읽는 독자는 없다. 그래서 **로드맵**이 핵심 내비게이션이다(roadmap.sh).
2. **읽는 책이 아니라 훈련하는 서비스다.** 장은 실습·퀴즈·통과 기준으로 끝난다. 그래서 장은 **레슨**처럼 한 단계씩 진행한다(Brilliant·Duolingo).
3. **이론과 실습이 끊기지 않아야 한다.** 위젯과 코드 셀이 본문 단계 안에 있고, 연습문제는 같은 장 안에서 채점된다.

## 2. 정보 구조

```
머리: 로고 · 로드맵(지도) · 트랙 · 내 진도 · 검색(⌘K) · 테마
홈 ─ 소개 + 레이어별 트랙 카드
 ├─ 지도 /map/            레이어 × 트랙 의존 관계 (roadmap.sh 전체 로드맵)
 ├─ 트랙 /tracks/<key>/   그 트랙의 로드맵: 부(주제) → 장(하위 주제), 노드 서랍
 │   └─ 장 /<부>/<장>/     본문이 있으면 레슨 화면, 없으면 '다룰 내용' 카드
 ├─ 부 /<부>/              장 목록
 └─ 내 진도 /progress/     숫자 카드 · 트랙별 진행 · 내보내기·가져오기
```

## 3. 진도 모델 (roadmap.sh)

장마다 상태가 넷이다: 시작 전 · 학습 중 · 완료 · 건너뜀.
- 자동: 장을 열면 학습 중이 되고, 퀴즈·연습문제·통과 기준을 모두 마치면 완료가 된다.
- 수동: 로드맵 노드 서랍에서 학습 중·완료·건너뜀·초기화를 직접 고를 수 있다. 수동 선택이 자동 판정보다 우선한다.
- 저장: 브라우저 localStorage의 `roadmap:progress:v1`에 장 id를 키로 저장한다.

## 4. 학습 원칙 (화면과 무관하게 유지)

- **예측 → 관찰 → 설명.** 핵심 개념 앞에 확인 문제를 두고, 위젯과 코드로 확인한 뒤 해설한다.
- **본문은 JS 없이 읽힌다.** 위젯·편집기는 그 단계가 보일 때 활성화하고, Pyodide는 첫 실행 때 내려받는다(화면 맨 위 로딩 막대).
- **접근성.** 모든 조작은 키보드로 가능하다. `prefers-reduced-motion`이면 전환 애니메이션을 끈다.
