# 디자인 시스템

> 상태: **채택**([ADR 0007](decisions/0007-visual-design.md)). 시안: [디자인 시안 10선](https://claude.ai/artifact/MP1JMt5cjhcaSVvackXhzj)
> 화면 구조는 [ux-design.md](ux-design.md), 위젯 목록은 [`data/widgets.toml`](../data/widgets.toml).

## 1. 원칙

1. **테마는 하나, 효과는 적재적소.** 색·글꼴·모션 토큰은 사이트 전체에서 같다. 시각 효과는 기능이 요구할 때만 고른다. 한 페이지에 여러 효과가 함께 쓰여도 된다.
2. **움직임은 이해를 위해서.** 과정·변환·흐름·인과를 보여 줄 때 움직인다. 장식용 움직임은 쓰지 않는다.
3. **만져서 이해한다.** 이론·실습·퀴즈 어디서든, 값을 바꿔 보면 이해가 빨라지는 곳에는 직접 조작할 수 있는 컨트롤을 둔다.
4. **조작은 쉽고, 결과는 즉시.** 처음 보는 사람도 설명 없이 쓸 수 있고, 손을 떼기 전에 결과가 보인다.
5. **심플하고 간결하고 세련되게.** 화면에는 지금 필요한 것만 둔다. 주석처럼 덧붙인 작은 글씨(보조 설명, 종류 표시, 개수 나열)는 쓰지 않는다. 설명이 필요하면 본문이나 컨트롤 자체가 말하게 한다.
6. **스크롤 대신 넘기기.** 긴 내용을 한 페이지에 쌓아 스크롤시키지 않는다. 단계(장의 절), 탭(연습문제·부), 한 번에 한 문항(퀴즈)으로 나누고 버튼·탭 바·진행 막대로 이동한다. 전환에는 방향이 있는 짧은 애니메이션을 쓴다(§4 모션 토큰, `prefers-reduced-motion`이면 끈다).

**화면 단위 규칙** ([ADR 0009](decisions/0009-paged-reading.md))

| 대상 | 단위 | 이동 |
|---|---|---|
| 장 | 절(`##`) 하나가 한 단계 | 위쪽 단계 막대(누르면 이동), 아래 이전·다음 버튼, ←·→ 키 |
| 본문 속 퀴즈 | 버튼 하나 → 문항 카드(대화상자) | 닫으면 읽던 자리 |
| 개념 퀴즈 | 한 번에 한 문항 | 진행 막대, 다음 문항 버튼 |
| 연습문제 | 연습문제마다 탭, 그 안에서 문제·코드·해답 탭 | 탭 바 |
| 트랙·목차 | 부마다 탭, 레이어마다 탭 | 탭 바 |
| 페이지 사이 | 교차 페이드(View Transitions) | 링크 |
| 기다림 | 화면 맨 위 로딩 막대 | 브라우저 Python 불러오기·실행, 페이지 이동 |

## 2. 색

브랜드는 메인 2색 + 엣지 1색이다. 화면의 90%를 메인 2색이, 10%를 엣지가 차지한다.

| 역할 | 이름 | 값 | 다크 테마 | 라이트 테마 |
|---|---|---|---|---|
| 메인 1 | Midnight | `#0B1020` | 바탕(60%) | 글자·어두운 면(30%) |
| 메인 2 | Glacier | `#DCE6F2` | 글자·밝은 면(30%) | 바탕(60%) |
| 엣지 | Coral | `#FF6B5A` | 10% | 10% |

- **엣지는 "지금 볼 곳"에만 쓴다:** 현재 위치, 주 실행 버튼, 슬라이더의 현재 값, 진행 표시, 선택된 항목. 장식·제목·아이콘 전체에 쓰지 않는다.
- **중립색**은 메인 두 색 사이의 단계(Midnight 쪽으로 약간 푸른 회색)로 만든다. 선·비활성·보조 텍스트에 쓴다.
- **의미 색은 엣지와 별개다.** 정답 `#2BA87F`, 경고 `#E0A100`, 오류 `#D63B5C`. 색만으로 의미를 전하지 않고 항상 아이콘·문구를 함께 쓴다.
- **트랙은 색으로 구분하지 않는다.** 트랙 코드 배지(`MTH`, `SML` …)와 아이콘으로 구분한다. 색을 트랙마다 나누면 2+1 규칙이 무너진다.
- 위젯의 데이터 계열이 여러 개 필요하면 Glacier·Midnight의 명도 단계와 엣지 1색으로 먼저 해결하고, 그래도 부족할 때만 보조 계열색을 쓴다(위젯 단위로 정의하고 대비 기준을 확인).

## 4. 모션 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--dur-instant` | 100ms | 슬라이더·호버 반응 |
| `--dur-quick` | 200ms | 버튼·토글·피드백 |
| `--dur-move` | 320ms | 패널 전환, 카드 이동 |
| `--dur-explain` | 600–1200ms | 과정 설명 애니메이션의 한 단계 |
| `--ease-out` | `cubic-bezier(.2,.8,.2,1)` | 기본 |
| `--ease-inout` | `cubic-bezier(.65,0,.35,1)` | 상태 사이 모핑 |

- 설명 애니메이션은 언제나 **재생·일시정지·한 단계·되감기**가 가능하다.
- `prefers-reduced-motion`이면 애니메이션 대신 단계별 정지 화면으로 같은 정보를 준다.
- 화면 밖의 캔버스·시뮬레이션은 멈춘다.

## 5. 효과 도구 상자

시안 10선의 효과를 **도구**로 둔다. 기능에 맞는 것을 고르고, 한 페이지에서 여러 개를 함께 써도 된다.

| 효과 | 이럴 때 쓴다 | 예 |
|---|---|---|
| Floating dock + ⌘K | 사이트 전체 이동 | 전역 셸 |
| 성좌 그래프(경로 추적) | 의존·경로·관계를 보여 줄 때 | 로드맵 지도, 선수 지식 경로 |
| 3D 레이어 스택 | 계층 구조를 보여 줄 때 | 레이어 L0–L6, 신경망 층 |
| 선 그리기(draw-on) + 치수선 | 정적인 도식·유도를 단계적으로 보일 때 | 기하 도식, 회로·장치 도면 |
| 스크롤 무대(sticky stage) | 글을 따라 상태가 바뀌는 과정 | SVD, 확산 forward/reverse, 학습 루프 |
| 모핑 전이 | 두 상태의 관계를 보여 줄 때 | 원 → 타원, 사전 → 사후 분포 |
| 입자·흐름장 시뮬레이션 | 연속체·확률 과정·물리 현상 | 유체, 기상, 확산, 이온 이동 |
| 분할 실험대 | 이론과 코드를 오가며 실습할 때 | 코드 셀, 연습문제 |
| 터미널 + 체크리스트 | 명령 실습 | 리눅스·환경 실습 |
| 벤토 타일 + 숫자 전이 | 요약·진도 | 트랙 개요, 내 진도 |
| 키네틱 타이포 | 단락의 시작을 알릴 때 | 부 표지, 트랙 소개 |
| 유리 패널(blur) | 배경 위에 떠 있는 보조 정보 | 도크, 명령 팔레트, 장 머리 카드 |

## 6. 인터랙션 원칙

### 6.1 파라미터 컨트롤 (슬라이더)

이론을 배울 때 "이 값을 바꾸면 어떻게 되지?"가 생기는 곳에는 슬라이더를 둔다.

- **이름·값·단위가 항상 보인다.** 라벨은 수식의 기호와 같게(`τ`, `σ`, `b₁`), 값은 JetBrains Mono로, 물리량은 단위와 함께(`0.50 A`).
- **의미 있는 범위와 눈금.** 최솟값·최댓값·기본값을 표시하고, 특별한 값(0, 1, 임계값)에서 살짝 붙는다(snap).
- **즉시 반응.** 끄는 동안(100ms 이내) 그림·수식·코드 값이 함께 바뀐다. 계산이 무거우면 미리보기를 먼저 그리고 손을 떼면 정밀 계산한다.
- **정밀 조절.** 키보드 ←/→로 한 단계, Shift와 함께 10단계, 값을 눌러 숫자로 직접 입력.
- **프리셋과 되돌리기.** 대표 상황(예: 항등·전단·특이)을 칩으로 제공하고, 언제나 "처음으로"가 있다.
- **연결 강조.** 수식의 기호에 마우스를 올리면 해당 슬라이더와 그림의 요소가 함께 강조된다. 반대도 마찬가지다.
- **모바일.** 터치 영역 44px 이상, 슬라이더 손잡이는 크게, 가로 스크롤과 충돌하지 않게.

### 6.2 직접 조작

- 그림 안의 점·벡터·경계는 손잡이로 직접 끈다. 끌 수 있는 요소는 손잡이 모양과 커서로 알 수 있게 한다.
- 제약이 있으면(예: 단위원 위의 점) 손잡이가 제약을 따라 움직이고, 왜 멈추는지 표시한다.

### 6.3 과정 재생

- 단계가 있는 개념은 타임라인(재생·일시정지·한 단계·되감기·드래그)으로 보여 준다.
- 각 단계에 짧은 문장 설명이 붙는다. 소리 없이도, 움직임 없이도 이해할 수 있어야 한다.

### 6.4 비교

- "있을 때 / 없을 때"(bias 켜기·끄기, 정규화 유무, 무작위 분할 vs 그룹 분할)는 토글이나 좌우 분할로 보여 준다. 토글은 같은 화면에서 상태만 바꿔 차이가 눈에 띄게 한다.

### 6.5 상태와 안전

- 위젯·코드·퀴즈는 페이지 상태를 공유하고, 사용자가 바꾼 상태는 브라우저에 저장된다.
- 모든 조작은 되돌릴 수 있다. 막다른 상태(그림이 사라짐, 오류로 멈춤)가 생기면 이유와 복구 버튼을 보여 준다.
- 접근성: 모든 컨트롤은 키보드로 조작되고, 위젯은 현재 상태를 문장으로도 제공한다(스크린 리더용).

## 7. 기능별 인터랙션

### 7.1 이론

- 개념 절마다 **예측 → 조작 → 설명**: 먼저 퀴즈 한 문항으로 예측하게 하고, 위젯을 조작해 확인한 뒤, 해설이 차이를 설명한다.
- 정적인 도식은 선 그리기로, 과정은 스크롤 무대나 타임라인으로, 매개변수 의존성은 슬라이더로.

### 7.2 실습

- 분할 실험대: 이론 패널 ↔ 편집기 ↔ 그래프 ↔ 테스트 콘솔이 같은 변수를 공유한다.
- 슬라이더로 코드의 상수를 바꿀 수 있다(코드 속 숫자를 끌어서 조절). 바뀐 값은 코드에도 그대로 반영된다.
- 테스트는 통과한 항목부터 하나씩 체크되며, 실패하면 무엇이 기대와 달랐는지 값으로 보여 준다.

### 7.3 퀴즈

- 선택지 카드: 오답을 고르면 그 선택지의 피드백 → 다시 시도, 정답이면 해설.
- **슬라이더 응답:** 수치 문항은 슬라이더로 답할 수 있다(`quiz.toml`의 `slider`). 예: "선형 영역의 개수는?"을 1–8 슬라이더로.
- **확인해 보기:** 해설 아래에 관련 위젯을 문항의 상황으로 맞춰 여는 버튼을 둔다.
- 계획: 위젯 상태가 조건을 만족하면 통과하는 **위젯 미션**(예: "det A = 0이 되게 만들어라")을 별도 형식으로 추가한다.

### 7.4 이동과 진도

- 전역 이동은 floating dock과 ⌘K. 장 안의 이동은 페이지 목차와 단계 표시줄.
- 진도는 벤토 타일과 성좌 지도의 점등으로 보여 준다.

## 8. 위젯의 종류

`data/widgets.toml`의 `kind`로 위젯이 어떤 인터랙션 틀을 쓰는지 정한다. 프론트엔드는 종류별 공통 틀(컨트롤 배치, 재생 바, 비교 토글)을 하나씩 만든다.

| `kind` | 인터랙션 | 공통 틀 |
|---|---|---|
| `manipulate` | 슬라이더·손잡이로 매개변수를 바꾸며 관찰 | 그림 + 파라미터 패널 + 프리셋 + 처음으로 |
| `stepper` | 단계가 있는 과정을 재생 | 그림 + 타임라인 + 단계 설명 |
| `simulate` | 시간에 따라 진행하는 시뮬레이션 | 캔버스 + 재생·속도 + 매개변수 패널 |
| `compare` | 두 조건의 차이를 비교 | 토글 또는 좌우 분할 + 차이 강조 |
