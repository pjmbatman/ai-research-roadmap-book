# 목차 설계 근거

이 문서는 [OUTLINE.md](../OUTLINE.md)의 구조가 **왜 이렇게 생겼는지** 기록한다. 목차를 바꿀 때는 이 문서의 원칙과 충돌하는지 먼저 확인한다.

## 1. 출발점

출발점은 "20개 대분류·80개 장" 초안(ChatGPT 답변)이었다. 그 초안의 좋은 점은 그대로 가져왔다.

- 이론 · 구현 · 연구 · 운영의 **네 축 병행**
- 모든 장의 **공통 형식**(학습 목표 · 선수 지식 · 핵심 개념 · 실습 · 실패 사례 · 통과 기준)
- **필수 / 심화 / 참조** 구분
- 목차 순서와 **학습 순서(5단계 나선형)**의 분리
- 기간이 아닌 **산출물로 진도 판단**

## 2. 바꾼 것과 이유

### 2.1 트랙(Track)이라는 상위 분류를 추가했다

190개 장을 평평한 20개 부로 나열하면 독자가 지도를 그릴 수 없다. 부를 7개 트랙으로 묶었다.

| 트랙 | 부 | 성격 |
|---|---|---|
| 시작하기 | 0–1 | 목표·읽는 법·연구의 전체 지도·첫 파이프라인 |
| 연구 작업대 | 2–6 | 첫 주부터 필요한 도구와 코드 규칙 |
| 수학적 기초 | 7–14 | 이론 축 |
| 모델링 | 15–21 | 데이터에서 신뢰성까지 |
| 연구 실천 | 22–23 | 실험 운영과 연구 방법론 |
| 도메인 | 24–25 | Scientific ML, 배터리 AI |
| 연구실 | 26 | 표준화와 종합 프로젝트 |

트랙은 웹 UI에서 색으로 구분되고, 사이드바의 1단계 그룹이 된다. 디렉터리 깊이는 늘리지 않았다(트랙은 frontmatter 값이다).

### 2.2 작업대(환경·도구)를 수학보다 앞에 두었다

초안은 수학(Ⅲ–Ⅵ) 뒤에 Linux·환경·Git(Ⅶ–Ⅸ)이 왔다. 그러나 신입 연구원이 **첫 주에 막히는 곳은 수학이 아니라 서버 접속과 환경**이다. 학습 경로 1단계("작은 파이프라인 완주")가 작업대를 요구하므로 목차 순서도 그에 맞췄다.

### 2.3 "첫 번째 연구 파이프라인" 장을 새로 만들었다 (1.4)

나선형 학습의 진입점. 책 전체를 한 번 얕게 관통하고, 각 부가 이 파이프라인의 어디를 깊게 파는지 연결한다.

### 2.6 수치해석을 독립 부로 키웠다

배터리·공학 연구에서 시뮬레이터와 solver는 데이터 생성기이자 baseline이자 오차의 원천이다. 부동소수점(9.1)부터 DAE·시뮬레이터 검증(9.7)까지 7장.

## 3. 유지할 원칙

1. **한 장 = 한 학습 단위.** 장이 두 가지 목표를 가지면 나눈다.
2. **모든 장은 산출물로 끝난다.** 통과 기준이 "이해한다"로 끝나면 다시 쓴다.
3. **선수 지식은 최소로.** 꼭 필요한 직전 장만 적는다(전이적으로 따라가면 된다).
4. **필수(core)는 "모든 연구원이 직접 할 수 있어야 하는 것"만.** 현재 190장 중 139장이 필수다 — 집필하면서 심화로 내릴 후보를 계속 검토한다.
5. **도구는 개념과 절차로 가르치고, 버전·화면은 갱신되는 참조로 둔다.**
