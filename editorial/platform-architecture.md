# 플랫폼 아키텍처

> 상태: **설계 초안.** 전제: **오픈소스로 공개, 로그인 없음, 예제는 CPU로 돌아가는 가벼운 규모.**
> UX는 [ux-design.md](ux-design.md), 콘텐츠 규칙은 [conventions.md](conventions.md).

## 1. 결론: 정적 사이트 + 실행 런타임 어댑터

로그인이 없고 예제가 가벼우면 **백엔드·DB·계산 서버 없이** 서비스할 수 있다. 코드는 **학습자의 CPU**에서 돈다.

| 구성 요소 | 필요 여부 | 이유 |
|---|---|---|
| 프론트엔드 (정적 사이트) | **필요** | 본문·위젯·편집기·퀴즈·진도를 모두 브라우저에서 처리 |
| 백엔드 | 불필요 | 로그인·서버 채점·작업 관리가 없다 |
| DB | 불필요 | 진도는 브라우저 저장소에 두고 파일로 내보내기·가져오기 |
| 계산 서버 | 불필요 (선택) | 코드는 학습자의 브라우저(WebAssembly) 또는 학습자 컴퓨터의 Python에서 실행 |

정적 파일만 있으면 되므로 GitHub Pages 같은 무료 정적 호스팅으로 공개할 수 있다. 서버를 운영하지 않으니 남용·보안·비용 문제가 거의 없다.

## 2. 런타임 어댑터

코드 셀과 연습문제는 **실행 위치를 모른다.** 셀은 "무엇이 필요한가"(`exec`)만 선언하고, 프론트엔드의 런타임 어댑터가 연결된 런타임 중 조건을 만족하는 것을 고른다.

```
   코드 셀 / 연습문제  ── exec="browser" | "python" | "gpu"
            │
            ▼
   ┌──────── Runtime 인터페이스 ────────┐
   │ connect · run · interrupt · reset │
   └──┬───────────────┬────────────────┬┘
      ▼               ▼                ▼
  PyodideRuntime   LocalRuntime      RemoteRuntime (선택)
  브라우저          학습자 컴퓨터의     기관 서버·Binder 등
  (Web Worker)     Jupyter 커널       Jupyter 호환 서버
  학습자 CPU        학습자 CPU/GPU     원격 자원
```

| 어댑터 | 실행 위치 | 설치 | 가능한 것 | 쓰는 곳 |
|---|---|---|---|---|
| **Pyodide** (기본) | 브라우저 안 WebAssembly, 학습자 CPU | 없음. 첫 실행 시 내려받음 | NumPy·SciPy·pandas·matplotlib·scikit-learn 등 Pyodide 패키지 | 수리 기초·확률·통계·고전 ML·NumPy로 구현한 신경망 |
| **Local** | 학습자 컴퓨터의 Python (`labs/` 환경) | `uv`로 실습 환경 설치 후 런타임 실행 명령 1개 | 실습 환경 전체(PyTorch 포함), 파일·셸 | 딥러닝(PyTorch)·연구 코드·터미널 실습 검사 |
| **Remote** (선택, 나중에) | 기관 서버 또는 공개 Jupyter 호환 서비스 | 없음 | 서버 환경 | 강의·워크숍 등 설치가 어려운 상황 |

- **코드 셀 `exec` 값**은 요구 수준이다. [conventions.md §10](conventions.md)
  - `browser`: Pyodide에서 돈다. 모든 어댑터에서 실행 가능.
  - `python`: 실습 환경 전체가 필요(PyTorch 등). Local·Remote에서 실행.
  - `gpu`: CUDA가 필요. GPU가 있는 Local·Remote에서만. 소수의 장(분산 학습·profiling)에만 쓴다.
- 조건을 만족하는 런타임이 연결되어 있지 않으면 셀은 코드와 **미리 기록된 실행 결과**를 보여 주고, "로컬 런타임 연결 방법"과 노트북 내려받기 링크를 함께 보여 준다. 실행하지 못해도 읽을 수는 있다.
- **세션:** 같은 `session` 이름의 셀은 같은 인터프리터 상태를 공유한다(Pyodide는 Worker 하나, Local은 커널 하나).

### 2.1 Pyodide 어댑터

- Web Worker에서 실행해 계산 중에도 화면이 멈추지 않게 하고, 중단 버튼을 둔다.
- 첫 실행 때 런타임과 패키지를 내려받는다(수 MB~수십 MB, 이후 브라우저 캐시). 페이지를 열 때가 아니라 **실행 버튼을 처음 누를 때** 내려받는다.
- WebAssembly는 네이티브 Python보다 느리다. 브라우저 예제는 **몇 초 안에 끝나는 크기**로 쓴다.
- **PyTorch는 브라우저 실행을 가정하지 않는다**(Pyodide 공식 패키지로 확인되지 않음 — 구현 시점에 다시 확인). 딥러닝 장은 같은 개념을 NumPy 구현으로 먼저 브라우저에서 보여 주고, PyTorch 버전은 `exec="python"`으로 둔다.

### 2.2 Local 어댑터

- 학습자가 자기 컴퓨터에서 실습 환경을 띄우면, 사이트가 `localhost`의 Jupyter 호환 커널에 연결해 코드를 보낸다. 학습자의 CPU(있으면 GPU)를 그대로 쓴다.
- 실행 명령은 저장소에 런처 스크립트로 제공한다(예: `labs/`의 실행 명령 하나). 런처가 Jupyter 서버의 플래그·토큰·허용 출처 설정을 대신해, 본문이 특정 버전의 플래그에 의존하지 않게 한다.
- **보안:** `127.0.0.1`에만 바인딩, 무작위 토큰 필수, 허용 출처(origin)를 이 사이트로만 제한. 사이트의 코드가 학습자 컴퓨터에서 학습자 권한으로 실행된다는 사실을 연결 화면에서 명확히 알린다. 원하는 학습자를 위해 컨테이너로 런처를 띄우는 방법도 제공한다.
- **브라우저 정책:** 공개 웹사이트가 `localhost`에 접속하면 브라우저가 로컬 네트워크 접근 허용을 묻는다(Chrome의 Local Network Access). 연결 버튼을 누를 때만 요청하고, 허용이 필요하다는 안내를 미리 보여 준다.
- 터미널 실습(INF 트랙)도 이 어댑터로 검사한다: 학습자는 자기 터미널에서 과제를 수행하고, 사이트가 연결된 커널로 검사 스크립트를 실행해 통과 여부를 표시한다. 연결하지 않은 학습자는 같은 검사 스크립트를 직접 실행한다.

### 2.3 Remote 어댑터 (선택)

강의·워크숍처럼 설치 없이 바로 써야 하는 상황을 위한 확장 지점이다. Local 어댑터와 같은 Jupyter 호환 프로토콜을 쓰므로, 주소와 토큰만 다른 같은 구현으로 붙일 수 있다. 자체 서버를 쓸 경우 신뢰할 수 없는 코드 실행에 대한 격리(작업별 컨테이너, 네트워크 차단, 자원 제한, 연구 데이터와 분리)를 갖춘 뒤에만 공개한다.

### 2.4 실행과 채점의 흐름

모든 단계가 학습자 쪽(브라우저 또는 학습자 컴퓨터)에서 일어난다. 이 사이트의 서버로 코드나 결과가 가는 일은 없다.

| 실습 | ① 작업 | ② 실행 | ③ 결과 반환 | ④ 채점 (브라우저) |
|---|---|---|---|---|
| 코드 실습 (`browser`) | 브라우저 편집기 | 같은 페이지의 Web Worker(Pyodide) | Worker → 페이지 | 테스트 실행 결과 표시 |
| 코드 실습 (`python`·`gpu`) | 브라우저 편집기 | 학습자 컴퓨터의 커널 (`localhost`) | 커널 → 페이지 | 테스트 실행 결과 표시 |
| 터미널 실습 | 브라우저 터미널 창(커널의 터미널에 연결) 또는 학습자 자신의 터미널 | 학습자 컴퓨터의 셸 | 검사 스크립트 결과 → 페이지 | 체크리스트 자동 체크 |
| 개념 퀴즈 | 브라우저 | — | — | 답안 키와 대조 |

- **코드는 정답 코드와 문자열로 비교하지 않는다.** 같은 문제를 푸는 올바른 코드는 여러 개다. 대신 **테스트**를 실행한다: 정해진 입력에 대한 출력, 수치 허용 오차, shape·성질(예: 대칭, 보존량) 검사.
- **터미널 실습은 입력한 명령이 아니라 결과 상태를 검사한다.** 예: 파일이 생겼는가, 권한이 맞는가, 환경이 재현되는가, 프로세스가 떠 있는가.
- **브라우저 터미널 창은 학습자 컴퓨터의 실제 셸이다.** 학습자 권한으로 명령이 실행되므로 연결 화면에서 이를 알리고, 연습용 컨테이너 안에서 런처를 띄우는 방법을 기본으로 권한다. 런타임을 연결하지 않은 학습자는 자기 터미널에서 같은 검사 스크립트를 직접 실행한다.
- 퀴즈만 답안 키와 직접 대조한다.

## 3. 상태 저장 (로그인 없음)

| 데이터 | 저장 위치 | 비고 |
|---|---|---|
| 진도(장별 읽음·실습·통과) | 브라우저 저장소(IndexedDB/localStorage) | 장 `id` 기준. 장 순서가 바뀌어도 유지 |
| 퀴즈 응답 | 브라우저 저장소 | 문항 `id` 기준 |
| 편집한 코드 | 브라우저 저장소 | 셀별 "원래 코드로 되돌리기" |
| 백업·기기 이동 | **JSON 파일 내보내기·가져오기** | 서버 없이 기기 간 이동 |

- 브라우저 저장소는 사용자가 지우면 사라진다. 진도 화면에 내보내기 버튼을 항상 둔다.
- 스터디·강의에서 진도를 확인하고 싶다면, 내보낸 JSON을 제출받는 운영 방식으로 해결한다(서비스에 계정 기능을 넣지 않는다).

## 4. 채점과 공개 범위

오픈소스이므로 **정답·테스트·해답은 모두 공개된다.** 시험이 아니라 학습 도구로 설계한다.

- 퀴즈: 브라우저에서 즉시 채점. 오답 선택지별 feedback → 재시도 → 해설.
- 코드 연습문제: 테스트를 브라우저(또는 Local 런타임)에서 실행해 즉시 결과를 보여 준다. 해답은 화면에서 접힌 상태로 제공하고, 일정 횟수 시도 후 펼치기를 권한다.
- 통과 기준 체크리스트: 학습자가 스스로 체크한다(자기 평가). 문서 산출물·리뷰형 과제는 스터디·커뮤니티·지도교수가 사람으로서 확인한다.

## 5. 빌드와 배포

```
이 저장소 (Git = 유일한 원천)
  content/ · quiz.toml · data/widgets.toml · labs/exercises/
        │  CI: book.py check → 사이트 빌드 → 연습문제 해답이 모든 테스트를 통과하는지 확인
        ▼
  정적 파일 → 정적 호스팅(GitHub Pages 등) → 학습자 브라우저
                                          ├─ Pyodide (학습자 CPU)
                                          └─ (선택) localhost 커널 (학습자 컴퓨터)
```

- 브라우저 실행 코드 셀의 출력은 빌드 시 미리 실행해 기록해 둔다(실행 전에도 결과가 보이고, 코드와 결과가 어긋나면 CI가 잡는다).
- Pyodide 런타임 파일은 CDN을 쓰거나 사이트와 함께 배포한다(버전 고정).

## 6. 기술 선택 (제안)

| 영역 | 제안 | 이유 |
|---|---|---|
| 사이트 | **Astro** + React 아일랜드 | 정적 본문은 빠르게, 인터랙티브 요소만 골라 활성화 |
| 수식 | KaTeX | 빠른 렌더링, 위젯 값과 연동한 동적 수식 |
| 편집기 | CodeMirror 6 | 가볍고 모바일 대응 |
| 브라우저 실행 | Pyodide (Web Worker) | 과학 계산 패키지, 학습자 CPU 사용, 서버 0 |
| 로컬 실행 | Jupyter 호환 커널 + 저장소의 런처 | 표준 프로토콜, PyTorch 포함 실습 환경 그대로 |
| 시각화·모션 | D3, Motion, 필요 시 Three.js | 역할별 최소 조합 |
| 상태 저장 | IndexedDB(또는 localStorage) | 로그인 없는 진도 |
| 호스팅 | 정적 호스팅 + CI 배포 | 운영 비용 0 |

## 7. 저장소 구조 (확장안)

```
content/  labs/  data/  editorial/  templates/  scripts/   ← 현재 (책)
apps/web/                프론트엔드 (Astro)
  src/runtimes/          런타임 어댑터 (pyodide, local, remote)
  src/widgets/<name>/    위젯 구현 (data/widgets.toml의 name과 일치)
labs/pyproject.toml      실습 환경 (Local 어댑터와 노트북 공용) + 런처
```

백엔드·DB·계산 서버 디렉터리는 만들지 않는다. Remote 어댑터를 붙이게 되면 그때 `services/`를 추가한다.
